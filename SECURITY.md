# Security Policy

## Supported version

OpsFlow is currently developed from the `main` branch. Security fixes are applied to the latest revision of that branch; older commits and local forks are not maintained as separate release lines.

## Reporting a vulnerability

Please use [GitHub private vulnerability reporting](https://github.com/laolei888/OpsFlow/security/advisories/new) and do not disclose exploitable details in a public issue, discussion, pull request, or screenshot.

Include the affected endpoint or component, prerequisites, reproducible steps, impact, and any safe proof of concept. Remove real credentials, personal information, access tokens, and production data before submitting a report.

The maintainer will acknowledge a complete report as soon as practical, validate the issue, and coordinate remediation and disclosure through the private advisory. Reports may be written in Chinese or English.

## Safe testing

Only test systems and accounts you own or are explicitly authorized to assess. Do not perform denial-of-service testing, access other users' data, persist access, send unsolicited messages, or degrade a shared environment.
