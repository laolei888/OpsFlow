# 前端架构说明

OpsFlow 前端采用 Vue 3 + Vite，并以渐进方式从单文件工作台演进为模块化应用。第一轮重构先稳定路由、会话、权限、请求和布局边界，后续业务页面按同一边界继续拆分。

## 目录职责

- `src/app/`：页面元数据和导航配置。
- `src/router/`：Hash 路由和角色访问守卫，避免服务端额外配置 SPA 回退。
- `src/stores/`：Pinia 全局状态；当前集中管理登录会话。
- `src/services/`：统一 HTTP、鉴权、追踪编号和文件下载处理。
- `src/composables/`：可复用权限判断等组合逻辑。
- `src/constants/`：领域状态与中文显示字典。
- `src/components/common/`：错误、提示、状态等无业务组件。
- `src/components/layout/`：侧栏和顶部栏等应用骨架。
- `src/views/`：路由级页面；登录页已经独立，其他页面按后续重构计划迁移。

## 路由约定

登录后的工作区使用 Hash 路由，例如 `/#/tickets`。这样开发环境和 Spring Boot 静态资源部署都可直接刷新，不依赖 Web Server 增加回退规则。工单详情使用可分享、可刷新的动态路由 `/#/tickets/:ticketId`，而不是依赖列表页临时弹窗状态。`/status` 和 `/sso/callback` 仍由后端控制器转发到前端入口。

路由元数据使用 `authenticated`、`staff`、`admin` 三种访问级别。菜单会按权限过滤，路由守卫同时阻止手动输入越权地址；后端 RBAC 仍是最终安全边界。

## 请求约定

业务组件通过统一 `request(path, options)` 调用后端：

1. 自动附加 JWT。
2. JSON 请求自动设置内容类型，`FormData` 保留浏览器生成的 boundary。
3. 401/403 清理会话。
4. 错误信息附带 `X-Trace-Id` 或 `X-Request-Id`，便于定位后端日志。
5. CSV 等文件下载复用统一鉴权和错误处理。

## 后续拆分规则

每个路由级业务页面应只负责页面编排；API 调用进入 `services/`，跨页面状态进入 `stores/`，领域标签进入 `constants/`，可复用交互进入 `components/common/`。禁止继续向根 `App.vue` 增加新的完整业务模块。

## 工作空间与导航

导航按工作空间、服务管理、运营响应、治理交付、平台管理和可靠性六个业务域组织。菜单配置、路由标题和面包屑共用 `src/app/navigation.js`，避免同一页面在多处重复维护名称与权限。

`workspace` Store 在本地保存以下个人偏好：

- 侧栏展开或收起状态。
- 每个导航分组的展开状态。
- 最多 8 个收藏入口。
- 最近 6 个访问页面。

总览页根据角色呈现不同工作重点：REQUESTER 关注申请与确认，AGENT 关注 SLA、紧急事项和待认领队列，ADMIN 关注审批、活跃问题和平台异常。角色化展示只影响入口与信息密度，所有数据权限仍由路由守卫和后端 RBAC 共同约束。

## 工单详情工作流

`views/TicketDetailView.vue` 是独立路由页，并采用按需加载，避免继续扩大首屏 JavaScript。页面分为三个协作区域：

- 主内容区负责问题描述、附件证据和知识推荐。
- 协作区按时间合并审计日志与公开回复 / 内部备注。
- 上下文侧栏集中展示 SLA、负责人、工单事实和关联配置项。

状态按钮不在组件中散落硬编码。`app/ticketWorkflow.js` 维护与后端一致的状态动作、五阶段进度和 SLA 风险计算，并由 Node 测试覆盖客服与提单人的不同操作边界。驳回和重新打开等高影响操作要求填写原因，再把原因写入协作记录，使流程交接和审计更完整。

处理人不能直接把工单标记为已解决。处于 `IN_PROGRESS` 的工单必须提交结构化解决包，包括解决类型、解决摘要和验证结果，服务端随后原子地将状态推进到 `WAITING_CONFIRMATION`。只有原申请人可以验收：确认后进入 `RESOLVED` 并触发满意度邀请；选择“仍有问题”时必须填写原因，工单原子地退回 `IN_PROGRESS`。列表页、批量更新和通用状态接口都不能绕过这一闭环，解决包及每次提交、确认、退回动作均进入详情页和审计时间线。

经过申请人确认的解决方案可由客服从详情页一键沉淀为内部知识草稿。草稿自动整理问题现象、影响范围、已有尝试、解决方案和验证结果，并保留来源工单 ID 与编号。数据库对租户和来源工单建立唯一约束，接口同时采用幂等返回，重复点击或并发请求不会生成多篇草稿。生成后仍需客服检查敏感信息、补充适用范围并人工发布，系统不会把工单内容直接公开。

## 引导式工单创建

`components/tickets/CreateTicketWizard.vue` 将创建流程拆成场景选择、上下文补充、影响确认三个步骤。标题和分类会提前查询知识库，为用户提供自助解决入口；影响问卷通过 `app/ticketIntake.js` 给出可解释的优先级建议，用户仍负责最终确认。

问题描述、影响范围、期望结果和已尝试措施作为独立字段提交。向导支持随请求附带一个不超过 10 MB 的证据文件，工单成功创建后再进入附件安全扫描，附件失败不会回滚已经生成的工单。组件按需加载，关闭时直接销毁本地草稿，避免半成品状态泄漏到其他页面。
