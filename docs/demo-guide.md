# OpsFlow 8 分钟演示指南

这套演示围绕“员工 VPN 远程接入失败”展开，目的是用一条连贯业务链路展示平台，而不是逐页浏览功能。

## 0. 演示前准备

1. 启动环境：`docker compose up -d --build`
2. 执行基础验收：`node quality/final-acceptance.mjs`
3. 使用 ADMIN 账号执行演示数据脚本：

```powershell
$env:OPSFLOW_DEMO_USERNAME = "你的管理员账号"
$env:OPSFLOW_DEMO_PASSWORD = "你的密码"
node quality/demo-seed.mjs
```

脚本会创建或复用一组带 `[OPS-DEMO]` 标记的数据，不会一次性导入大量无关记录。

## 1. 开场：说明业务问题（30 秒）

“OpsFlow 是一个面向企业 IT 服务管理的工单与知识协同平台。我主要负责后端，系统把员工报障、支持组处理、SLA、知识沉淀、配置项影响分析和运维治理连接成闭环。”

## 2. 工单队列与批量能力（1 分钟）

- 打开“工单中心”，搜索 `[OPS-DEMO]`。
- 展示每行前的选择框，勾选指定工单后再导出，强调不会默认导出整批数据。
- 打开 VPN 工单，说明状态机、优先级、处理人、支持组和 SLA 字段。

## 3. 支持组与并发安全（1 分钟）

- 展示工单已路由到 `Network Operations（演示）`。
- 说明客服领取工单时会校验组成员资格；状态更新采用乐观锁，重复创建可使用 `Idempotency-Key`。
- 如果时间允许，领取工单并流转到处理中。

## 4. CMDB 关联与影响分析（1 分钟）

- 在工单详情展示关联的 `VPN 核心接入网关（演示）`。
- 进入 CMDB 查看配置项的环境、关键等级和业务系统。
- 说明告警、事件、变更和工单共享配置项上下文，从“处理一张单”提升到“判断业务影响”。

## 5. 知识库闭环（1 分钟）

- 搜索并打开《VPN 接入故障排查手册（演示）》。
- 打开“知识治理”，展示脱敏、适用范围和验证步骤三项门禁，以及 `草稿 → 待审核 → 已发布` 流程。
- 说明只有管理员可审核发布，驳回原因、撤回动作、版本历史和 180 天复核日期均可追溯。
- 将知识文章的排查步骤与当前工单对应起来。

## 6. 服务目录与审批（1 分钟）

- 打开服务目录的“员工 VPN 接入”项目。
- 展示 `[OPS-DEMO] 新员工 VPN 权限开通` 待审批申请。
- 说明服务目录将标准申请与故障工单分流，审批后仍能进入统一处理和审计链路。

## 7. 企业级技术亮点（2 分钟）

- 安全：Spring Security + JWT + BCrypt，结合角色、租户和资源归属校验；支持 OIDC/SSO。
- 一致性：业务事务先写 Transactional Outbox，再由 RabbitMQ 异步投递；消费侧提供重试、死信、重放和幂等治理。
- 可观测性：Actuator/Micrometer + OpenTelemetry，Prometheus、Grafana、Loki、Tempo 组成指标、日志、链路体系。
- 可靠性：灾备计划、签名备份代理回调、恢复演练和受控混沌实验均有审计记录。
- 质量：Flyway V57，319 项后端单元/组件测试及 6 项 MySQL 集成测试。

## 8. 收尾（30 秒）

“这个项目的重点不是页面数量，而是我用一个真实 ITSM 场景练习了多租户权限、状态机、幂等、异步消息、审计、可观测性和容灾治理等 Java 后端能力。”

演示结束后可执行 `node quality/final-acceptance.mjs --strict-auth`，用机器可读结果证明关键链路仍然可用。
